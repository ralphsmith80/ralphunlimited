Run time in the automated standings

Three ways to show how long each run took in the standings table on /lab/. Every table below uses the real published data, including the run times that the next publish adds.

Each cell is the model's best-scoring run on that benchmark, the same as today. The time is the time of that run. A dash means the run has no recorded time: the July runs and the old retro-cruiser runs.

Option A

Time inside the score chip

The small label under each score changes from "view" to the run time. Nothing else on the page changes.

Good
  • Smallest change. The table stays the same size.
  • You see the score and the time together.
Weaker
  • The time is small, so comparing many cells takes effort.
  • The "view" and "gate" hint is gone. A failed gate still shows as a grey 0.
Option B

A "Run time" view in the toggle

A third button joins "Harness score" and "Player rating". In this view each chip shows the time, shaded by speed across every run in the table: bright is fast, dark is slow. Click the buttons to switch.

fastest middle slowest no time recorded
Good
  • Large, easy-to-compare numbers. The shading makes fast and slow runs clear at a glance.
  • Follows the toggle pattern the table already uses for player ratings.
Weaker
  • You cannot see the score and the time at the same moment.
  • One more control to learn.
Option C

Time line under each chip

The score chip stays as it is. Under it, a thin bar and the time. All bars use one scale, the slowest run in the table, so you can compare any cell with any other cell.

Good
  • Score and time are both visible, with no toggle.
  • The bars make long runs easy to spot across the whole table.
Weaker
  • Each row gets taller, so the table is longer.
  • Busier to look at.
