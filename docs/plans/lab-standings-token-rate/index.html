Token rate in the standings

Three ways to add output tokens per minute to the "Automated standings" table on /lab/. Each mock is a copy of the real table with the same styles and the same rows.

The run list mock uses "out tok/min", a short subline, and a hover card. These mocks use the same number, words, and hover card, so the two pages match.

Sample data: the Void Cruiser 3D column has the eight sample token runs from the run list mock. All other runs have tokens: null, as they will at first. Hover or focus any rate to see the full count.

Out tok/minoutput ÷ (durationMs ÷ 60,000). Null when tokens or run time is missing.
Which runEach cell shows the model's best run for that benchmark. Its rate can be null when an older run has the best score.
Never reportedCursor, Grok, and Antigravity do not give token counts. Their cells stay empty for good.
Option 1

A rate line under the run time

Each cell gets one more short line under its time bar, for example "2,482 out tok/min". Cells with no tokens say "no tokens", in the same faint style as "no time". Use the switch to see the rate and time on one line.

/lab/ · src/pages/lab/index.astro, inside each standings cell
Layout
Good
  • Speed and time sit together, and the rate uses that time.
  • No new control. The toggle stays as it is.
Weaker
  • Until more runs report tokens, most cells say "no tokens". The "Time line" layout hides that noise: a null rate shows nothing.
  • Every row gets about 14px taller in the "Own line" layout.
What it touches
  • lab.ts: a tokenRate(run) helper next to runTime, and the tokens field on LabRun.
  • index.astro: one <span class="rate-line"> after the time line. Show it only when some run in the table has tokens, like showTimes. Add one legend item.
  • lab.css: .rate-line and .rate-line.none, plus the hover card. The card must be fixed or placed by script, because .matrix-wrap scrolls and clips anything that overflows it.
Option 2

A third toggle: Output speed

The toggle gets "Output speed" next to Harness score and Player rating. In that mode each chip shows its rate. A fill from the left shows the rate against the fastest run in the table. Chips with no tokens look like unrated chips in Player rating mode. The legend changes with the mode.

/lab/ · src/pages/lab/index.astro, toggle, chips, legend, and the paint() script
Good
  • Cells stay the same height. The data only shows when a reader asks for it.
  • The fill gives a rate scale that you can read at a glance.
Weaker
  • With few token runs, this mode is mostly empty chips for now.
  • A reader cannot see speed and score at the same time.
What it touches
  • index.astro: a third toggle button; data-rate, data-rate-pct, and token data attributes on each chip; a "rate" branch in paint(); a second legend that swaps in.
  • The toggle is hidden until Convex connects today. Output speed needs no Convex, so show the toggle when token data exists, and hide only the Player rating button without Convex.
  • lab.css: .chip.rate, .chip.norate, and a third button colour.
Option 3

A speed column at the end of each row

The cells do not change. A new last column gives each model's median out tok/min across all its runs that reported tokens, with a bar on a shared scale and a run count. Null rows say why: the agent never reports, or no run has tokens yet.

/lab/ · src/pages/lab/index.astro, one more th and td per row
Good
  • One number per model is easy to compare down the column.
  • It uses every run with tokens, not only the best run per cell, so it fills in faster.
Weaker
  • It mixes benchmarks. A slow 3D build and a fast rebuild give one median.
  • The table gets wider. On a phone the column needs the scroll.
What it touches
  • lab.ts: standings() also collects each model's token runs (not only the best), and a median helper.
  • index.astro: one header cell and one summary cell per row. The null text uses the agent name.
  • lab.css: th.sum-h and td.sum. table.matrix min-width goes from 620px to about 780px.
